# ぬいぐるみあつめ レベル3：ハテナの箱と条件分岐（IF文）🎁🦐🧻

## Problem Statement
実行するたびに中身が変わる不確実な状況（ランダムな箱）の中で、「目的のアイテム（エビ）だけを選んで拾い、不要な罠（紙）をスルーする」というプログラミングの条件分岐（IF文）の必然性を、猫たちの可愛い世界観と挫折しないフィードバックを通じて子どもたちが直感的に理解できるようにするにはどうすればよいか？

---

## Recommended Direction

### 1. ランダムな「ハテナの箱 🎁」によるIF文の必然性の創出
盤面に2つの箱が並び、実行（またはリセット）するたびに中身（「🦐 エビのぬいぐるみ」と「🧻 トイレットペーパー」）がランダムに入れ替わります。
ホムラがそのマスに入ると自動で「パカッ！」と箱が開き、中身が現れます。「あける」ブロックをあえて作らず自動オープンにすることで、子どもがつまずくことなく**「中身を判断して行動する（条件分岐）」という本質**に集中できます。

### 2. 直感的なC型IFブロック `toki_if`
教育用プログラミングの王道であるC型ブロックを採用します。
```text
┌ もし あしもとが [ 🦐エビ ▼ ] なら
└ これをする：
    [ ぬいぐるみを ひろう 🐾 ]
```
条件に当てはまるときだけ内側のブロックを実行します。将来のレベル4で「くりかえし」の中にそのまま組み込める美しい構造です。

### 3. 一本道コースと優しいペナルティ演出
2つの箱を順番に通り抜けてからトキへ向かうステージ構成とします。これにより「片方の箱だけ見に行く運ゲー」を防ぎ、「両方の箱をチェックしてエビの時だけ拾う」という完全なロジックを促します。
もし間違えて紙を拾ってしまった場合も即ゲームオーバーにはせず、トキの元へ行ったときに**「トイレットペーパーで イタズラしちゃダメニャ〜！🧻💦 エビを もってきてね！」**と優しく教えてもらい、自分で気づいて修正できるようにします。

## Key Assumptions to Validate
- [ ] **ランダム変化の理解度**: 実行するたびに箱の中身が変わることで、子どもが「あっちに行けばいい」という目視の決め打ちを諦め、「プログラムに判断させる（IF文）」という思考に自然とシフトできるか。
- [ ] **C型ブロックの操作性**: タッチ操作やマウスで、C型ブロックの内側（`これをする`）に「ひろう」ブロックを迷わずドラッグ＆ドロップして挿入できるか。
- [ ] **箱の自動オープンタイミング**: マス進入時にテンポよく箱が開き、子どもが「開いた！」と認識した上でIF判定が行われる自然な演出になっているか。

## Not Doing（あえてやらないこと・理由）

- **「はこを あける」アクションブロックの独立**  
  *理由*: 手数が増え、「あけ忘れ」という本質的でない操作ミスで挫折するのを防ぐため。
- **「そうでなければ（ELSE）」の同時導入**  
  *理由*: 初めて条件分岐を学ぶ子どもにとって情報過多になるため。まずはシンプルな「条件成立時のみ実行」に絞る。
- **複雑な条件式組み立て（式パーツのはめ込み）**  
  *理由*: 「A == B」のような論理演算パーツの組み立ては認知負荷が高すぎるため、ドロップダウンで対象を選べる日常語の完結型Cブロックにする。
- **紙を拾った瞬間の即ゲームオーバー**  
  *理由*: トキホムラボの「怒られない・失敗から楽しく学べる」という世界観を維持するため。
