# 🐱 猫たちの大きさ比べソートモード（Cat Size Sort Mode）

## Problem Statement
子どもたちが「特定の問題を解く手順（固定の決め打ち）」から脱却し、「どんな順番で並んでいても自動で小さい順に並び替える汎用プログラム（アルゴリズム）」の凄さと面白さを、「マンチカン・アメショ・サイベリアン」という個性豊かな猫たちの大きさ比べと2レーン同時テストを通じて直感的に体感できるようにするにはどうすればよいか？

---

## Recommended Direction

### 1. モチーフとビジュアル：3種類の猫たちと「大きさ比べ」
- 従来の5×5グリッドとは異なる、横並びの「大きさ比べステージ」を導入します。
- 画面には、サイズと特徴が明確に異なる3種類の猫たちが並びます。
  - **マンチカン（小 / 1）**: 小柄で短い手足がチャームポイント
  - **アメショ（中 / 2）**: 標準的な体格のしましま猫（アメリカンショートヘア）
  - **サイベ（大 / 3）**: 体が大きくモフモフでボリューミーな大型猫（サイベリアン）
- 各猫の頭上や名札に「小（1）」「中（2）」「大（3）」のアイコン・数字バッジを併記し、視覚的な直感と数字の比較をスムーズに繋ぎます。
- プレイヤーの分身として「トキ監督」（レベル2では「ホムラ監督」も登場）が猫たちの足元に立ち、「いま比較している2匹のペア」を虫眼鏡やマークで指し示すことで、ポインタ（カーソル）の概念を可視化します。
- 「いれかえる」が実行されると、2匹の猫が「ニャッ！」と跳ねて位置を入れ替わるコミカルで分かりやすいアニメーションを提供します。

### 2. 操作系とアルゴリズム
バブルソートの根本原理である「隣接比較」「交換」「走査」を、子ども向けのシンプルなブロック群で実現します。
- **レベル1**: まずは手動の順序づけ（シーケンス）でアルゴリズムを体感できるよう、3つの基本ブロックのみを使用します。
  - `いれかえる 🔄` (`sort_swap`)
  - `つぎの ペアへ すすむ ➡️` (`sort_step_next`)
  - `さいしょに もどる ⏪` (`sort_reset_pointer`)
- **レベル2**: 条件分岐と反復を活用した汎用アルゴリズムへステップアップします。
  - `もし [ひだり ＞ みぎ] なら 【これをする】` (`sort_if`)
  - `〇かい くりかえす 🔁` (`toki_repeat`)

### 3. レベル設計と2レーン同時テスト
- **レベル1（1レーン固定：さいしょにもどる を使わないと解けないパズル）**:
  - トキ組の3匹が `[サイベ(大), アメショ(中), マンチカン(小)]`（`[3, 2, 1]`）で初期配置。
  - 1巡の走査（入れ替える ➔ 次へ進む ➔ 入れ替える）だけでは `[中, 小, 大]` までしか並べ替えられず、**`さいしょに もどる ⏪` を使って先頭に戻り、もう一度入れ替えないとクリアできない** 構造になっています。
  - これにより「端まで行ったら最初に戻る」というソートアルゴリズムの本質的なステップを自然に学びます。
- **レベル2（トキ＆ホムラ 2レーン並列テスト）**:
  - 上レーン（トキ組: `[サイベ(大), アメショ(中), マンチカン(小)]`）と下レーン（ホムラ組: `[アメショ(中), サイベ(大), マンチカン(小)]`）が同時に表示。
  - 1つのプログラムを実行すると、トキ監督とホムラ監督が**まったく同じ命令を同時に実行**しながら、それぞれのレーンで異なる条件分岐を経て、最終的に両方のレーンが「小さい順（マンチカン ➔ アメショ ➔ サイベ）」に整列すればクリア！
  - 「1つのアルゴリズムが、違う並び順のどちらも綺麗に解決する」というプログラミング本来の威力を体感できます。

## Key Assumptions to Validate
- [ ] **猫種の識別しやすさ**: マンチカン（小）・アメショ（中）・サイベ（大）のグラフィック差（体格・毛足・耳や尻尾）とバッジにより、低学年でも大小関係が一目で迷わず認識できるか。
- [ ] **ポインタ移動の理解**: 「いま誰と誰を比べているか」が、監督猫の立ち位置や足元ハイライトだけで迷わず理解できるか。
- [ ] **3匹という要素数の適切さ**: 3匹（ペア数は2箇所）に絞ることで、二重ループを組まなくても「端まで走査＋最初に戻る」を数回繰り返すだけで子どもが自力で正解に到達できるか。
- [ ] **端到達時のフェイルセーフ**: 一番右端（2番目と3番目のペア）にいる状態でさらに「つぎのペアへすすむ」を実行した際、画面外に行かず「ここが はしっこニャ！」と優しく留まる安全設計になっているか。
- [ ] **並列テストの爽快感**: トキ組とホムラ組が同時に動いて両方揃った瞬間に、十分な達成感と驚きが得られるか。

## Not Doing（あえてやらないこと・理由）

- **4匹以上の猫の整列**  
  *理由*: 4匹以上になるとアルゴリズムが複雑化し、多重ネストループが必要になって小学生の認知負荷を超えるため。
- **大きい順（降順）ソートの混在**  
  *理由*: まずは「小さい順（昇順）」に一本化し、比較演算子（＞ と ＜）の切り替えによる混乱を防ぐため。
- **クイックソート・マージソート等の高度アルゴリズム**  
  *理由*: ビジュアルプログラミングで視覚的に追いやすく、日常の直感に近い「隣同士の大きさ比べ（バブルソート）」にフォーカスするため。
- **ステップ数・計算量のスコアリング競争**  
  *理由*: 最適化を競わせるよりも、「どんなパターンでも動くプログラムができた！」という成功体験を最優先するため。
