# ぬいぐるみあつめモード（Plush Toy Collection Mode）🐾🦐

## Problem Statement
子どもたちが「移動」だけでなく「場所に応じたアクションの実行（ひろう）」や「クリアのための前提条件（アイテムをすべて集めてからゴールする）」というプログラミングの重要概念を、認知負荷を抑えながら猫たちの可愛い世界観のなかで直感的に学べるようにするにはどうすればよいか？

---

## Recommended Direction

### 1. 「モード切替タブ」による基礎と応用の明確な分離
画面上の問題選択エリアに **「🐾 おにごっこ（きほん）」** と **「🦐 ぬいぐるみあつめ（おうよう）」** の切り替えタブを導入します。
おにごっこ（トキがホムラをつかまえる）に対し、ぬいぐるみあつめでは**ホムラを操作して、ぬいぐるみを集めてトキに届ける**という対比構造を採用します。
初めて触る子どもが遊ぶ「おにごっこ」では余計なブロックを見せず、「ぬいぐるみあつめ」に切り替えた時だけツールボックスに「ぬいぐるみを ひろう 🐾」ブロックが登場する動的ツールボックス構造を採用します。

### 2. 明示的なアクション実行と優しいフィードバック
通過での自動回収ではなく、同じマスで「ひろう」ブロックを実行することで回収される仕様とします。これにより「移動」と「アクション」のシーケンス（手順）を学ぶことができます。
また、子どもの挫折を防ぐため、ぬいぐるみのない場所で「ひろう」を実行した場合は即ゲームオーバーとはせず、「あれ？ ここには ぬいぐるみが ないよ？（キョロキョロ）」と優しく教えて次の命令へ進む仕様とします。

### 3. 直感的な進捗把握とゴール条件
画面上部に「ぬいぐるみ：🦐 1 / 2」のようなシンプルな収集状況バッジを表示します。すべてのぬいぐるみを集めずにトキのマスへ到達した場合は、トキが「まだ ぬいぐるみが たりないニャ〜！」と吹き出しで教えてクリア判定を持ち越します。

 ---

 ## Key Assumptions to Validate
 - [ ] **空振り時の挙動**: ぬいぐるみのないマスで「ひろう」を実行した際にエラー終了せず注意喚起に留めることで、子どもが挫折せずに自力で間違いに気づいて修正できるか
 - [ ] **カウンタUIの視認性**: 画面上の「🦐 1 / 2」表示だけで、低学年の子どもが「あと何個必要か」を直感的に把握できるか
 - [ ] **タブ切り替えの発見しやすさ**: 初見のユーザーが迷わず基本編を終えたあとに応用編のタブへ気付けるか

 ---

 ## MVP Scope

 ### 含まれるもの（In Scope）
 - **モード切り替えUI**: 「おにごっこ」「ぬいぐるみあつめ」を切り替えるタブ
 - **操作キャラクターとゴールの切り替え**:
   - おにごっこ: トキ操作、ホムラがゴール
   - ぬいぐるみあつめ: ホムラ操作、トキがゴール
 - **新規カスタムブロック**: `toki_pickup`（「ぬいぐるみを ひろう 🐾」）のBlockly定義
 - **動的ツールボックス**: モードに応じたブロックパレットの切り替え表示
 - **ぬいぐるみの盤面描画**: グリッドセル上にぬいぐるみアイコン（🦐 エビ / 🎾 ボール）を配置
 - **収集状況カウンターUI**: 画面上で集めた個数がリアルタイムにわかるバッジ表示
 - **ぬいぐるみあつめ専用ステージ**:
   - ステージ1（初級）: 盤面のまんなかに1個のぬいぐるみ（🦐 エビ）があり、拾ってから右下のトキへ行く
   - ステージ2（中級）: 2個のぬいぐるみ（🦐 エビ・🎾 ボール）があり、ダンボールを迂回しながら回収してトキへ行く
 - **クリア＆空振りフィードバック演出**:
   - 未回収でトキ接触時の吹き出し
   - 空振り時のホムラのキョロキョロ演出と吹き出し
- **Playwright 自動テスト**: 新規ブロックの動作、アイテム回収、未回収時の挙動を検証

## Not Doing（あえてやらないこと・理由）

- **マス通過による自動回収**  
  *理由*: 「移動」と「アクション実行」というプログラミングのメソッド呼び出しの概念を学ぶ機会を損なうため。
- **空振り時の即座ゲームオーバー**  
  *理由*: 子ども向けゲームにおいて理不尽なストレスとなり、学習意欲を削ぐため。
- **既存ステージ（レベル1〜4）へのアイテム後付け**  
  *理由*: 既存の洗練された学習難易度曲線を壊さず、まずは基礎をしっかりマスターできるようにするため。
- **おもちゃを使う・置くコマンド**  
  *理由*: 最初からコマンドが多すぎると混乱するため、まずは「拾ってゴールする」の一方向シーケンスに集中する。
- **複雑なインベントリ画面やアイテムスロット**  
  *理由*: 画面を圧迫して盤面が見づらくなるのを防ぐため、シンプルなカウント表示のみとする。
