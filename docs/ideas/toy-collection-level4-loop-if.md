# ぬいぐるみあつめ レベル4：パトロール街道と自動スキャン（くりかえし × もし）🤖🔁❓

## Problem Statement
子どもたちが「1マスずつ手動で書く大変さ」と「ループと条件分岐を組み合わせて自動判定させる爽快さ」の落差を体感し、プログラミング（アルゴリズム）の真の便利さと楽しさに感動できるようにするにはどうすればよいか？

---

## Recommended Direction

### 1. 「おもちゃパトロール街道（1直線スキャン型）」のステージ設計
スタート地点からゴール（トキ）まで、上下をダンボールで挟まれた直線通路を移動します。
通路の途中に3つのハテナ箱（🎁）が並んでおり、中にはそれぞれ「🦐 エビのぬいぐるみ」「🎾 ボールのぬいぐるみ」「🧻 トイレットペーパー（トラップ）」が入っています。
トキのところへ行くには、**エビとボールの両方を拾い、トイレットペーパーは拾わずにゴール**する必要があります。

```text
[スタート: ホムラ] ─▶ [ 🎁 箱1 ] ─▶ [ 🎁 箱2 ] ─▶ [ 🎁 箱3 ] ─▶ [ゴール: トキ]
  (0, 2)               (1, 2)       (2, 2)       (3, 2)         (4, 2)
  ※ 上の行 (Y=1) と 下の行 (Y=3) はダンボールで塞がれた安全な1本道
```

### 2. 「手動の限界」から「ループの必然性」への気づき
1マス進むごとに箱が自動で開き、何が入っているか分からないため、手動で解く場合は：
「すすむ ➔ もしエビならひろう ➔ もしボールならひろう ➔ すすむ ➔ もしエビならひろう ➔ もしボールならひろう…」
と、15個以上のブロックを繋げる必要があります。
解くこと自体は可能ですが、「長くて大変！」「途中でわけが分からなくなる！」という体験をあえて許容します。

### 3. スマートな解法（アルゴリズム的思考・★3評価）
「同じ確認と前進を繰り返している」ことに気づくと、わずか **7ブロック** のエレガントなコードに昇華します。

```text
┌ 3かい くりかえす 🔁
│   まえに 1マス すすむ 🐾
│   ┌ もし あしもとが [ 🦐エビ ▼ ] なら
│   └   ぬいぐるみを ひろう 🐾
│   ┌ もし あしもとが [ 🎾ボール ▼ ] なら
│   └   ぬいぐるみを ひろう 🐾
└
まえに 1マス すすむ 🐾 （トキにタッチ！）
```
子ども自身が「自動おそうじロボット」や「検品センサー」のようなアルゴリズムを作れたという強烈な達成感を得られます。

## Key Assumptions to Validate
- [ ] **複数条件（並列IF）の理解**: ループの中に「もしエビ」と「もしボール」の2つを連続して入れる構造が、小学生低学年〜中学年にも無理なく理解できるか。
- [ ] **★3ブロック数設定の適切さ**: 愚直解（15ブロック以上）とスマート解（6〜7ブロック）の差がはっきりと星評価（minBlocks）に反映され、試行錯誤のモチベーションになるか。
- [ ] **メッセージの分かりやすさ**: エビとボールの両方が必要なこと、トイレットペーパーを拾ってはいけないことが、開始時メッセージと失敗時メッセージで直感的に伝わるか。

## Not Doing（あえてやらないこと・理由）

- **「ELSE（そうでなければ）」や「AND / OR（論理演算）」ブロックの追加**  
  *理由*: 小学生向けの入門フェーズにおいて、直列の「もし」を2つ並べる方が視覚的・概念的に直感で把握しやすいため。
- **動くトキ（おにごっこ）との同時融合**  
  *理由*: 「箱の探索・選別」と「逃げる相手の追跡」を同時に行うと、失敗したときの原因特定が難しくなり、知育パズルとしての焦点がブレるため。
- **複雑な迷路・曲がり角の導入**  
  *理由*: 「向きを変える」処理がループに入ると一気に難易度が跳ね上がり、ループ×条件分岐の本質（スキャンアルゴリズム）の体験が薄れてしまうため。
