# ぬいぐるみあつめ レベル4：ハテナの箱とダンボールパトロール（センサー型IF × ループ探索）🤖🔁❓

## Problem Statement
子どもたちが「1歩ずつ手動で曲がって拾う大変さ」と「環境センサー型の条件分岐（目の前の障害物検知・足元検知）をループと組み合わせて自律エージェントのように全自動で盤面を攻略する爽快さ」を体感し、ロボット・アルゴリズム的思考の真の便利さと楽しさに感動できるようにするにはどうすればよいか？

---

## Recommended Direction

### 1. センサー型条件分岐ブロック「もし {位置} が {対象} なら」
従来の固定アイテム判定から、プログラミング教育およびロボット工学の基本である**環境センシング**へと進化させます。

```text
┌ もし [ めのまえ ▼ ] が [ ダンボール ▼ ] なら
└ これをする：
    [ みぎを むく ↷ ]

┌ もし [ あしもと ▼ ] が [ おもちゃ ▼ ] なら
└ これをする：
    [ ぬいぐるみを ひろう 🐾 ]
```
- **位置ターゲット (`TARGET`)**: `['あしもと', 'feet']` / `['めのまえ', 'front']`
- **対象アイテム (`ITEM`)**: `['おもちゃ', 'toy']` / `['ダンボール', 'obstacle']`（※後方互換性のため `🦐`, `🧻` 等もサポート）

### 2. 障害物とハテナ箱が点在する探索パズル盤面
5×5グリッド上に、ダンボール（📦）3個とハテナ箱（🎁）3個が散らばっています。

```text
(0,0) ホムラ ─▶ (1,0) ────▶ (2,0) 箱1 ──▶ (3,0) ────▶ (4,0) ダンボール1 (ぶつかる前に右折!)
                                                        │
(0,1)          (1,1) トキ ◀                      ▼ (3,1)
                 [ゴール]                                │
(0,2)          (1,2) ◀───                            ▼ (3,2) 箱2
                 ▲                                       │
(0,3) ダンボール3  │                                     ▼ (3,3)
(ぶつかる前に右折!) └── (1,3) ◀─── (2,3) 箱3 ◀─── (3,3) ────┘ (3,4) ダンボール2 (ぶつかる前に右折!)
```
- **スタート**: `(0, 0)`（ホムラ 🐈、右向き）
- **ゴール**: `(1, 1)`（トキ 🐾）
- **ダンボール (3個)**: `(4, 0)`, `(3, 4)`, `(0, 3)`
- **ハテナ箱 (3個)**: `(2, 0)` [🦐], `(3, 2)` [🎾], `(2, 3)` [🧸]

### 3. スマートな解法（自律走行アルゴリズム・わずか6ブロックで★3）
```text
┌ 10かい くりかえす 🔁
│   ┌ もし めのまえ が ダンボール なら
│   └   みぎを むく ↷
│   まえに 1マス すすむ 🐾
│   ┌ もし あしもと が おもちゃ なら
│   └   ぬいぐるみを ひろう 🐾
└
```
「壁/障害物を見つけたら右へ曲がり、おもちゃを踏んだら拾いながら進む」という極めて自然なアルゴリズムにより、散らばった盤面を綺麗に一周して全アイテムを回収し、ゴールへ到達します。

## Key Assumptions to Validate
- [ ] **センシングの概念理解**: 「目の前を調べる（壁にぶつかる前に対処する）」という先読みの思考が、子どもにとって直感的に理解できるか。
- [ ] **手動解とスマート解の落差**: 愚直に手動で進む場合（20ブロック以上）と、スマート解（6ブロック）の圧倒的な差が快感として伝わるか。

## MVP Scope

### 含まれるもの（In Scope）
- **ドメインロジック純粋関数 (`src/domain/condition.js`)**:
  - `getConditionTargetPos`: 向きとターゲット（あしもと/めのまえ）から判定対象座標を算出
  - `checkCondition`: 障害物（ダンボール）またはおもちゃ（未回収・非トラップ）の存在を判定
- **Blocklyブロック拡張 (`src/blockly/blocks.js`, `src/blockly/parser.js`)**:
  - `toki_if` に `TARGET`（あしもと/めのまえ）と `ITEM`（おもちゃ/ダンボール/エビ等）の2つのドロップダウンを設定
  - `toki_repeat` の選択肢を最大12回まで拡張
- **実行エンジン連携 (`src/execution/runner.js`)**:
  - `executeIf` が `checkCondition` を呼び出して条件判定を実行
- **レベルデータ更新 (`src/constants/levels.js`)**:
  - レベル4「ハテナの箱と ダンボールパトロール」を新配置（障害物3、箱3、ゴール(1,1)）で設定
- **単体・UIテスト (`tests/unit/condition.test.js`, `tests/ui/toy.spec.js`)**:
  - 判定ロジックの網羅的テストおよびPlaywright E2Eテスト

## Not Doing（あえてやらないこと・理由）
- **複雑なセンサー（左右・斜めなど）の追加**: まずは「目の前」と「足元」の2方向で十分な教育効果が得られるため。
- **ELSE（そうでなければ）の導入**: 単純な直列条件分岐の組み合わせで解けるようにし、認知負荷を抑制。
